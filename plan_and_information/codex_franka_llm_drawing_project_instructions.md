# Codex Instructions: LLM-to-Franka Drawing Control Project

Use this document as a Codex prompt, or save it in the repository as a planning/implementation guide. The goal is to prepare the robotics/control codebase before the final USD scene is ready. The final USD scene will later contain the Franka robot, a pen attached to the end-effector, and a drawing board/plane.

---

## 0. One-paragraph task for Codex

Build a Python codebase for an LLM-to-Franka drawing-control pipeline. The code should be able to parse a `DrawingPlan` JSON generated by an LLM, convert line/arc drawing primitives into time-sampled Cartesian pen-tip trajectories, transform those trajectories from board frame to robot base frame, compensate for the pen-tip tool offset, and provide controller modules for baseline Differential IK and a future hybrid position-force controller. The core library must run without Isaac Sim or a final USD scene by using mock interfaces and unit tests. Isaac Sim / Isaac Lab integration should be isolated in backend modules and left as a clean placeholder until the actual USD scene is available.

---

## 1. Project context

This is a robotics term project. The application is:

```text
Natural-language command
→ LLM planner
→ line/arc drawing primitive JSON
→ Cartesian drawing trajectory
→ Franka robot control
→ pen draws on a board/plane
```

The LLM part already outputs high-level drawing primitives. This repository should focus on the robot-control side:

```text
LLM DrawingPlan JSON
→ trajectory sampler
→ frame transforms
→ pen-tip offset compensation
→ IK / Jacobian-based control
→ hybrid position-force controller
→ evaluation metrics and plots
```

The final simulator will use Franka, probably in Isaac Sim / Isaac Lab. However, the USD scene is not ready yet. Therefore, do not hard-code final USD paths, board pose, pen geometry, or specific prim names. Build a clean architecture with placeholders and mocks.

---

## 2. Main design decision

Do **not** implement the full Franka model, full Franka analytic IK, full analytic Jacobian, or simulator internals from scratch. Use simulator-provided or library-provided robot quantities when the Isaac backend is available.

Use existing simulator / library infrastructure for:

```text
- Franka articulation model
- joint state reading
- end-effector pose reading
- Jacobian acquisition
- mass matrix / gravity vector if available
- contact force reading if available
- basic simulation stepping
- baseline Differential IK examples or APIs
```

Implement ourselves:

```text
- LLM DrawingPlan parser
- line / arc primitive sampler
- time scaling
- board frame → robot base frame transform
- pen-tip → end-effector tool offset compensation
- robot backend abstraction
- pure-Python Differential IK fallback using damped least squares
- hybrid position-force controller math
- logging, metrics, and plotting
- unit tests and mock robot backend
```

The project contribution should be the LLM-to-robot execution pipeline and the contact-aware controller, not reimplementing the whole simulator.

---

## 3. Non-negotiable engineering constraints

1. The core modules must be independent of Isaac Sim.
   - No `omni.*`, `isaacsim.*`, or `isaaclab.*` imports inside core modules such as `trajectory`, `frames`, `controllers`, `evaluation`, or `llm_bridge`.
   - Isaac imports are allowed only inside `sim/` or `backends/isaac_*` modules.

2. The first version must run offline.
   - Provide a mock robot backend.
   - Provide unit tests that run with `pytest` without Isaac Sim.
   - Provide an example script that samples a plan and runs controller math using mock data.

3. Use SI units.
   - Position: meters.
   - Angles: radians.
   - Force: Newtons.
   - Torque: Newton-meters.

4. Do not assume the final board pose.
   - Load `T_base_board` from config.
   - Load `T_ee_tip` from config.
   - Provide reasonable placeholder defaults, but clearly mark them as placeholders.

5. Do not assume final prim names.
   - Use config fields such as `robot_prim_path`, `ee_frame_name`, `board_prim_path`, `pen_tip_frame_name` only in the Isaac backend placeholder.

6. Prefer small, typed, testable functions.
   - Use dataclasses or Pydantic-style simple validation where useful.
   - Avoid one giant script.

7. Keep controller code numerically safe.
   - Add damping in pseudo-inverse / DLS.
   - Clamp desired joint velocity, joint command, and torque where appropriate.
   - Return diagnostic data such as singular values and condition number.

## 5. Expected LLM output format

The LLM planner outputs a high-level `DrawingPlan` JSON. Support at least the following structure:

```json
{
  "actions": [
    {
      "name": "move_to_start",
      "params": {
        "target": {"x": 0.05, "y": 0.0, "z": 0.03, "unit": "m"}
      }
    },
    {"name": "pen_down", "params": {}},
    {
      "name": "draw_line_to",
      "params": {
        "target": {"x": 0.10, "y": 0.00, "z": 0.00, "unit": "m"},
        "speed_m_s": 0.03
      }
    },
    {"name": "pen_up", "params": {}}
  ]
}
```

Also support arc drawing:

```json
{
  "name": "draw_arc",
  "params": {
    "center": {"x": 0.0, "y": 0.0, "z": 0.0, "unit": "m"},
    "radius_m": 0.05,
    "start_angle_rad": 0.0,
    "end_angle_rad": 6.283185307179586,
    "direction": "ccw",
    "speed_m_s": 0.03
  }
}
```

Minimum supported action names:

```text
- move_to_start
- pen_down
- draw_line_to
- draw_line
- draw_arc
- pen_up
- align_pen_orientation
```

The planner output is not a robot trajectory yet. It is a geometric drawing plan in board-frame coordinates.

## 7. Frame convention

Use these frames:

```text
base frame:
    Robot base frame used by Franka / simulator.

board frame:
    Drawing plane frame. Origin is the drawing-board center by default.
    z = 0 is the drawing plane.
    +z is the board normal direction.

pen tip frame:
    Frame at the physical pen tip.
    Its origin touches the board during drawing.

end-effector frame / ee frame:
    Franka wrist or hand frame used by the simulator.
```

Required transforms:

```text
T_base_board:
    Board pose in robot base frame.

T_ee_tip:
    Pen-tip pose relative to end-effector frame.
```

Core equations:

```text
p_base = T_base_board * p_board
T_base_tip_des = T_base_board @ T_board_tip_des
T_base_ee_des = T_base_tip_des @ inverse(T_ee_tip)
```

Implement in `frames/transforms.py`:

```python
def make_transform(rotation: np.ndarray, translation: np.ndarray) -> np.ndarray

def invert_transform(T: np.ndarray) -> np.ndarray

def transform_point(T: np.ndarray, p: np.ndarray) -> np.ndarray

def transform_pose(T_a_b: np.ndarray, T_b_c: np.ndarray) -> np.ndarray

def rotation_from_board_normal(board_normal_base: np.ndarray, preferred_x_axis_base: np.ndarray | None = None) -> np.ndarray
```

Add tests:

```text
- inverse(T) @ T ≈ I
- transform_point identity works
- pose composition works
- generated rotation is orthonormal
```

```python
def sample_line(
    start: np.ndarray,
    end: np.ndarray,
    speed_m_s: float,
    dt: float,
    start_time: float = 0.0,
    rotation: np.ndarray | None = None,
    pen_contact_desired: bool = True,

    center: np.ndarray,
    radius_m: float,
    start_angle_rad: float,
    end_angle_rad: float,
    direction: str,
    speed_m_s: float,
    dt: float,

    rotation: np.ndarray | None = None,
    pen_contact_desired: bool = True,

```

Line formula:

```text
p(s) = p0 + s(p1 - p0)
```

Arc formula:

```text
theta(s) = theta0 + s * delta_theta
p(s) = [cx + r cos(theta), cy + r sin(theta), cz]
```

Handle direction:

```text
ccw: positive angular direction
cw: negative angular direction
```

Implement `trajectory/drawing_sampler.py`:

```python
def sample_drawing_plan(
    plan: DrawingPlan,
    dt: float,
    default_speed_m_s: float,
    hover_height_m: float,
    draw_height_m: float,
    default_normal_force_n: float | None = None,
) -> list[PoseSample]
```

Behavior:

```text
move_to_start:
    generate hover move with pen_contact_desired=False

pen_down:
    generate vertical move from hover z to draw z
    set pen_contact_desired=True near the end

draw_line_to / draw_line:
    generate drawing samples with pen_contact_desired=True

draw_arc:
    generate drawing samples with pen_contact_desired=True

pen_up:
    generate vertical move from draw z to hover z
    pen_contact_desired=False after lift
```

Do not assume the first drawing position is valid unless `move_to_start` is present. Validate action order and raise a clear error for invalid plans.

## 9. Baseline Differential IK controller

Implement `controllers/pose_error.py`:

```python
def orientation_error_axis_angle(R_des: np.ndarray, R_cur: np.ndarray) -> np.ndarray:
    """Return 3D orientation error vector using axis-angle/log-map style representation."""


def pose_error_6d(
    p_des: np.ndarray,
    R_des: np.ndarray,
    p_cur: np.ndarray,
    R_cur: np.ndarray,
    position_weight: float = 1.0,
    orientation_weight: float = 1.0,
) -> np.ndarray:
    """Return [position_error, orientation_error] with shape (6,)."""
```

Implement `controllers/diff_ik.py`:

```python
@dataclass
class DifferentialIKConfig:
    damping: float = 0.05
    position_gain: float = 1.0
    orientation_gain: float = 0.5
    max_delta_q: float = 0.05
    max_qd: float | None = None


@dataclass
class DifferentialIKDiagnostics:
    singular_values: np.ndarray
    condition_number: float
    delta_q_norm: float


class DifferentialIKController:
    def __init__(self, config: DifferentialIKConfig): ...

    def compute_delta_q(
        self,
        q: np.ndarray,
        jacobian_6xn: np.ndarray,
        p_des: np.ndarray,
        R_des: np.ndarray,
        p_cur: np.ndarray,
        R_cur: np.ndarray,
    ) -> tuple[np.ndarray, DifferentialIKDiagnostics]: ...

    def compute_q_target(...): ...
```

Use damped least squares:

```text
Δq = J^T (J J^T + λ² I)^-1 Δx
```

Where:

```text
Δx = [Kp_pos * (p_des - p_cur), Kp_ori * orientation_error]
```

Safety:

```text
- if J has wrong shape, raise ValueError
- if delta_q norm exceeds limit, scale it
- compute singular values
- condition_number = sigma_max / max(sigma_min, eps)
```

This controller is an offline fallback and a baseline. Later, Isaac Lab's DifferentialIKController may replace it in the Isaac backend, but keep this pure-Python version for testing and explanation.

## 10. Hybrid position-force controller

Implement `controllers/hybrid_position_force.py` as a pure math controller. It should not depend on Isaac.

Drawing task control split:

```text
board x/y tangent directions:
    position control

board z normal direction:
    force control or contact-force regulation

orientation:
    keep pen axis aligned with board normal
```

Selection matrices in board/task frame:

```text
S_p = diag(1, 1, 0)
S_f = diag(0, 0, 1)
```

Suggested config:

```python
@dataclass
class HybridPositionForceConfig:
    kp_pos_xy: float = 150.0
    kd_pos_xy: float = 20.0
    kp_z_when_not_in_contact: float = 100.0
    kd_z_when_not_in_contact: float = 10.0
    desired_normal_force_n: float = 1.0
    kp_force: float = 5.0
    ki_force: float = 0.0
    kd_force: float = 0.0
    max_force_cmd_n: float = 20.0
    max_torque_nm: float = 30.0
    orientation_kp: float = 20.0
    orientation_kd: float = 3.0
    nullspace_kp: float = 5.0
    nullspace_kd: float = 1.0
    use_gravity_compensation: bool = True
```

Suggested compute method:

```python
@dataclass
class HybridControllerDiagnostics:
    task_wrench: np.ndarray
    motion_wrench: np.ndarray
    force_wrench: np.ndarray
    orientation_wrench: np.ndarray
    tau_task: np.ndarray
    tau_null: np.ndarray
    tau_cmd_raw: np.ndarray
    tau_cmd_clipped: np.ndarray
    normal_force_error: float
    contact_active: bool


class HybridPositionForceController:
    def __init__(self, config: HybridPositionForceConfig): ...

    def reset(self) -> None: ...

    def compute_torque(
        self,
        q: np.ndarray,
        qd: np.ndarray,
        jacobian_6xn: np.ndarray,
        p_des_base: np.ndarray,
        R_des_base: np.ndarray,
        p_cur_base: np.ndarray,
        R_cur_base: np.ndarray,
        v_cur_base: np.ndarray | None,
        w_cur_base: np.ndarray | None,
        board_normal_base: np.ndarray,
        measured_normal_force_n: float | None,
        gravity_torque: np.ndarray | None = None,
        q_nominal: np.ndarray | None = None,
        dt: float = 0.01,
        contact_active: bool = False,
    ) -> tuple[np.ndarray, HybridControllerDiagnostics]: ...
```

Conceptual controller equation:

```text
F_motion = S_p [Kp_xy (p_d - p) + Kd_xy (v_d - v)]

F_force = S_f [F_d + Kf (F_d - F_n)]

F_orientation = K_R * orientation_error + D_R * angular_velocity_error

W_task = [F_motion + F_force, F_orientation]

τ_task = J^T W_task

τ_cmd = τ_task + τ_null + g(q)
```

Important details:

1. Force direction sign must be configurable or documented.
   - The board normal may point out of the board.
   - Contact force measured by the simulator may be force applied by board on pen or pen on board.
   - Add a config flag if needed: `normal_force_positive_when_pressing: bool`.

2. Before contact is active, use position control in z to move down safely.
   - Do not immediately command a large normal force when not in contact.
   - Use `kp_z_when_not_in_contact` until measured contact crosses threshold.

3. Once contact is active, regulate normal force.

4. Torque command should be clipped.

5. Return diagnostics for logging and evaluation.

## 11. Nullspace controller

Franka is redundant, so implement optional nullspace posture control in `controllers/nullspace.py`.

Suggested formula:

```text
N = I - J^+ J
τ_null = N^T [K_null (q_nominal - q) - D_null q_dot]
```

For now, use damped pseudo-inverse. Keep this optional. The default `q_nominal` can be loaded from config.

Add diagnostics:

```text
- nullspace torque norm
- joint-limit margin if joint limits are configured
```

## 19. Course-content mapping for report

Make it easy to explain the project in the final report:

```text
Homogeneous transformation:
    T_base_tip = T_base_board @ T_board_tip
    T_base_ee = T_base_tip @ inverse(T_ee_tip)

Trajectory planning:
    line and arc primitives are time-sampled using cubic time scaling.

Jacobian / Differential IK:
    x_dot = J(q) q_dot
    Δq = J_DLS^† Δx

Singularity handling:
    monitor singular values and condition number of J.

Force / torque relation:
    τ = J^T F_task

Robot dynamics:
    use gravity torque if available:
    τ_cmd = J^T W_task + τ_null + g(q)

Passivity / damping intuition:
    damping terms reduce energy-like error and improve stability.
```
